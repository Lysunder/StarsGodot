# S02 Turn order

Status: draft (2026-09-30). Top-level order read from `GenerateTurn` and its direct callees (with the disassembly
for arguments the decompiler lost). Order inside each phase is specified by the phase's own spec; this spec records
what is confirmed so far. Compared with the community "Order of Events" list.
References: `GenerateTurn@10a8:0000`, `DoWaypointTasks@10a8:0e92`, `DoWaypointTaskPass@10a8:3ec6`,
`MoveSpaceObjects@10a8:0f6e`, `MoveFleets@10a8:1f18`, `DoProduction@10b0:0000`, `RunBattles@10e8:24aa`,
`UpdateTechLevels@10b0:4c50`, `UpdateScoresAndVictory@10b0:3b78`, `RunComputerPlayers@1018:39f8`,
`WriteFileHeader@1068:53f8`.

## Summary

A turn is generated by one ordered list of phases. Every phase runs for all players and objects before the next
starts, so the order decides, for example, that fleets move before production and that battles happen after
production. The order also fixes the sequence of random draws (S01), which golden-turn tests depend on.

## Before turn generation

Computer players without an orders file make their orders (`RunComputerPlayers`), in the same program run and from
the same random sequence, just before turn generation. In our engine this is the AI step (S22); it is outside the
turn pipeline but its draws come first.

## Randomness

The phases that draw from the classic stream, in order (details in each spec): computer players (before the turn),
waypoint tasks that roll (S11), Mystery Trader movement and packets in phase 8, fleet movement and minefield checks
(9), mining (13a), random events (13e), wormholes and new packets (14), battles and bombing (16a), ground combat
(5c, 16d), `random(8)` (26) and one `random(2000)` per file written (27).

## Comparison with the community "Order of Events"

The community list agrees with most of the above. Differences found in the code:

| Topic | Community list | Code |
|---|---|---|
| Wormholes shift | after fleets move, before mining | after production, together with newly launched packets (phase 14) |
| Random events | after refueling, before battles | at the end of production, before new packets and refueling (13e) |
| Mass packets and salvage decay | after fleets move | inside the packet handling of phases 8 and 14 (S14 to confirm) |
| CA instaforming | before mine sweeping | Claim Adjuster terraforming runs after sweeping and repair (19); whether an instaform step also runs in task pass 4 is open (S10) |
| Remote mining | after meeting the MT | in task pass 3 (16c), after the MT; AR mining of its own worlds is part of mining (13a, S08) |
| Load order | waypoint load tasks in random player order | no random draw in the task passes: fleets are handled in owner order, then fleet number (S11; harness to confirm) |

## Edge cases

- A phase runs even when nothing applies to it (no fleets, no packets); random draws only happen for objects that
  roll.
- Phase order is the same every turn; the tutorial reseeds the generator first (1).

## Mod hooks

- Every row above is a `Phase` with the given id in the `TurnPipeline`. Mods can insert phases before or after any
  id, replace a phase, or disable it (MODDING §7). Sub-steps (5a–5f, 13a–13e, 16a–16f) are separate phases with ids
  like `wp0.unload`, `production.mining`, `wp1.battles`, so they can be targeted individually.
- Hooks: `on_turn_start` before phase 2, `on_turn_end` after phase 24.
